# Security review: Shark Audio (feature/shark-audio)

**Mode:** scoped SOURCE REVIEW by read-only auditor 5311fab6, plus RUNTIME tests run by the main agent.
**Scope:** shark.py, shark_api.py, server.py page routing and redirects, `/_app` static mount, the SvelteKit pages and lib, the Vite dev proxy, and new frontend dependencies.

## Findings

No Critical, High or Medium findings at confidence 0.8 or above.

Low (fixed): the version cap was checked before taking the lock, so two simultaneous revisions could create a 13th version. The check now runs again under `_lock` (`shark_api._render_version`). Regression test `test_version_cap_holds_even_when_the_unlocked_check_is_passed` passes with the fix and was shown to fail without it (RUNTIME).

Low (accepted, matches Studio): RuntimeError text from the local cloning engine is shown to the user. This is a single-user, loopback-guarded app.

## Controls verified

- Job ids must be 32 hex characters and exist. Chunk indexes and versions are integers checked against their lists, so file paths stay inside `WORK/<job>` (CODE; plus RUNTIME 404 tests).
- Input limits: 20,000 characters, 200 chunks, 20 speakers, voice-id pattern, 200-character notes, `extra="forbid"` (CODE; RUNTIME 422 tests).
- The shared `processing` slot is released on every path (CODE; RUNTIME 429 test).
- Redirects use fixed targets and pass only the query string, so there is no open redirect (CODE; RUNTIME tests).
- LocalAccess covers pages, `/_app` and `/api/shark` (RUNTIME `test_pages_keep_the_local_access_guard`).
- No `{@html}` or `innerHTML` in the Svelte sources (CODE).
- Frontend devDependencies are pinned exactly, with a lockfile. They were not installed globally, and there are no runtime npm dependencies.

## Not checked

LocalAccess internals beyond its use here, existing `render_line`/clone resolution, the content of the generated build, npm registry integrity hashes, and any runtime fuzzing. No whole-application security claim is made.
