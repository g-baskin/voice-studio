# Security review: Editor tab (feature/editor)

**Mode:** scoped SOURCE REVIEW by the implementing agent (no separate auditor was run), plus RUNTIME tests.
**Scope:** `editor.py`, `editor_api.py`, the `server.py` router and page registration, `frontend/src/lib/editor/`, `frontend/src/routes/editor/`, and the nav entry.

## Findings

Medium (fixed): ffmpeg opened uploaded files with every demuxer and protocol enabled. A file named `.mp4` that is really a concat or HLS playlist could make ffmpeg read other local files (or, on older ffmpeg builds, fetch URLs) into the preview or export. Every ffmpeg input that reads user media now passes `INPUT_GUARD` (`-protocol_whitelist file` plus a demuxer allowlist covering exactly the bin's supported formats) (`src/naturalvoice/editor.py:44`, used at the probe, waveform, proxy, thumbnail and export inputs). RUNTIME: `test_input_guard_stops_ffmpeg_following_a_playlist_to_other_files` passes with the guard and its unguarded half shows ffmpeg 9.0.2 following the playlist. `test_playlists_disguised_as_video_are_refused` covers HLS and absolute-path concat payloads. All 18 supported extensions were opened successfully under the guard.

Low (accepted): there is no total storage quota for Editor media. Each upload is capped at 2 GB and refused unless 1 GB of disk stays free (`editor_api.py:114`). Single-user local app.

Low (accepted, matches Studio): sequence and export JSON bodies are parsed before Pydantic's list caps (2,000 clips, 200 markers, 16 tracks) apply. Only same-origin, LocalAccess-approved clients can send them.

## Controls verified

- Media and sequence ids must be 32 hex characters (`identifier`). Stored files are always `source<allowed-suffix>`. The upload name is display text only (`Path(name).name`, 120 characters), so there is no path traversal (CODE; RUNTIME `test_unsupported_files_are_refused`).
- ffmpeg runs as an argument list, never a shell. Filtergraphs are built only from validated numbers and generated labels (CODE).
- Uploads are streamed with a declared, enforced length and removed on any failure (CODE; RUNTIME upload API tests).
- The shared `processing` slot bounds exports and media preparation, and is released on every path (CODE; RUNTIME 429 test).
- Export downloads are looked up by job key, and filenames are reduced to `[A-Za-z0-9 _.-]` (CODE).
- Premiere XML escapes every user string, and file URLs are percent-encoded (CODE; RUNTIME `test_premiere_xml_has_tracks_dissolves_levels_and_markers` with a space in the path and `<` in a marker).
- Removing media that a sequence uses is refused (CODE; RUNTIME test).
- LocalAccess covers `/editor` and `/api/editor` like every other page (RUNTIME `test_editor_page_is_served` and the existing access tests).
- No `{@html}` or `innerHTML` in the Editor's Svelte sources (CODE).
- No new dependencies (Python or npm).

## Not checked

ffmpeg's own decoder hardening against malformed media, behaviour with ffmpeg builds older than 9.0.2, LocalAccess internals, and fuzzing. No whole-application security claim is made.
