# QA report: Editor tab (feature/editor)

**Ordering:** the security review ran first (`2026-11-04-security.md`). Two later fixes (still-image speed in export, muted sound in Premiere XML) touch no input handling, uploads or file paths. Every check was run again on the final code.
**Plan source:** no PRD. The owner's request in session: an "Editor" menu tab with a familiar video-editor and clipping look, built on the SvelteKit pages, matching the app's light/dark theme. Chosen scope: multi-track (video and audio tracks, music ducking, transitions, Premiere Pro XML export).
**Reviewers:** implementing agent, plus one independent read-only reviewer (owl). The reviewer covered `editor.py`, `timeline.ts` and the Inspector speed controls, and reported CLEAR at 80%+ confidence. Its two lower-confidence notes were confirmed and fixed with regression tests.

## Warnings

None open. Fixed during QA:
- Still images with speed above 1 ended early in exports (`editor.py`, image input `-t`). Regression test: `test_sped_up_still_image_fills_its_clip`, which fails without the fix.
- Muted clips on audio tracks were still in the Premiere XML. Regression test: `test_premiere_xml_leaves_out_muted_sound`.
- The timeline grid shifted every cell, and the page scrolled sideways (`Timeline.svelte`, `+page.svelte`). Covered by the browser check's layout assertion.
- Builds were not reproducible because of random starter track ids in the prerendered page. Covered by `npm run frontend:check`.

## Suggestions

- Editor media lives in `DATA_DIR/editor`, which the Backup page does not include (`backup.ROOTS`). Media can reach 2 GB per file, so adding it needs a size decision.
- The preview plays the 540p proxies and draws cross-fades and opacity on a canvas. The export renders from the originals, so the preview is close to the final result but not identical.
- Not carried into Premiere XML: scale, position, fit/fill and ducking. The export dialog says so.
- No captions or titles track yet.
